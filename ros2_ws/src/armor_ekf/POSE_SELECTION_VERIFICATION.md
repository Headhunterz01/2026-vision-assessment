# 重投影跳框修复

日期：2026-10-09。此页记录 `REPROJECTION_VERIFICATION.md` 初版后，对实拍中预测板飞到机身外和静止机甲上的投影抖动的修复。初版数值验证保存在 [`06_重投影/results/initial_comparison_validation.json`](../../../06_重投影/results/initial_comparison_validation.json)；不保留可再生成的初版整段视频和缓存。修复后的结果图、验证数据位于 [`06_重投影/results/`](../../../06_重投影/results/)；最终视频 `four_plate_reprojection.mp4` 由你另行提供，不纳入 Git。

## 原因与修改

截图对应 `test.mp4` 第 978 帧（约 9.78 s）。同一块板的 IPPE 平面 PnP 产生两组有效姿态。旧流程用前一帧 EKF Yaw 的连续性挑选姿态，选了重投影 RMS 1.028 px 的镜像解，机器人中心投到图像 x≈970，旁边板的预测中心与检测相差约 239 px。另一解 RMS 0.622 px，中心投到 x≈723，旁边板中心相差约 20 px。测量板四角都能贴合，单靠该板的像素误差无法保证三维朝向正确。

在重投影模式中，新流程对每个有效 PnP 解都构造四板模型，并按以下证据选姿态：

1. 同帧其它检测板与正面模型板的轮廓交并比、中心距离。检测类别可能不同，因此比较所有检测板。
2. 上一次被多板几何支持的机器人中心，仅在中心接近且明显优于其它解时使用。
3. PDF 给定的装甲板 Pitch=15°，仅在两个姿态的俯仰差异足够明显且该解的重投影误差仍接近最小值时使用。
4. 证据不足且两个候选中心分离明显，或另一块检测板与所有候选都冲突时，当前帧不发布姿态/预测板；恢复可靠解后继续。目标切换或长时间中断会清除旧中心。

另一个现象是机甲近似静止时框仍偶尔跳动。YOLO 角点逐帧有约 1 px 量级的微小变化；平面 IPPE 通常同时给出两组外观接近、Yaw 相差约 7–8° 的姿态，因此微小角点噪声会让两解的重投影优劣次序互换。旧选择器会被模型 Pitch 先验或前一帧滤波角带到另一分支；而投影框直接使用原始 PnP，EKF 平滑并不能消除此抖动。修复保留上一帧实际选中的 PnP Yaw，只在候选误差与当前分支差异不超过 0.12 px 时保持当前分支；几何支持或误差明显更好的候选仍能切换。检测中断、时间回退或目标身份切换时清除该先验。

图像绘制四板中深度为正且投影与画面相交的所有板，包括背面模型板；背面框标注 `model back`。世界系 PoseArray 一直发布完整四板几何。漏检或姿态证据冲突时发布空 PoseArray 和 DELETE Marker。世界系 EKF 的旧模式不调用上述重投影选解逻辑。

## 验证

对同一份 3150 帧检测缓存，使用 `odom_gimbal_rpy=[0,0,0]` 这一**实拍对照参数**重放。它尚未经物理标定，不可用于机器人导航。

| 指标 | 初版 | 修复后 |
| --- | ---: | ---: |
| 有效模型帧 | 2280 | 2259 |
| 与其它检测板匹配的帧 | 959 | 938 |
| 其它板中心偏差中位数 | 17.7 px | 14.5 px |
| 其它板中心偏差 90 分位 | 255.4 px | 24.2 px |
| 中心偏差超过 100 px 的匹配 | 216 | 0 |
| 其它板轮廓 IoU 中位数 | 0.488 | 0.536 |

时间连续性对比同一实拍前 8 秒（401 个有效检测帧）：Yaw 相邻帧变化绝对值的 95 分位由 7.26° 降至 0.72°；超过 3° 的单帧变化由 34 次降至 15 次。少数大跳变仍存在，集中在姿态观测间断/跟踪重置附近；这说明剩余误差不是跨考核累计造成，而是当前视频检测噪声、平面 PnP 二义性和暂时失去连续跟踪共同造成。修复后的完整 3150 帧验证仍为 PASS，独立投影复算最大误差约 2.3e-13 px，其他板匹配中心误差 P90 为 24.9 px，超过 100 px 的匹配为 0。4/4 CTest 通过。

21 帧因证据冲突而不输出模型，表中匹配数因此不同。在新旧版本都保留的同一批 938 帧上，中心偏差超过 100 px 的匹配仍由 **209 降到 0**。其它检测板也来自同一个 YOLO 模型，没有永久物理标签，不能把匹配结果当作每帧真值。第 978 帧新图的中心落在机身两板之间，模型板框贴近机身；背面板也保留显示，并标明朝向状态。

构建后 4/4 CTest 通过；新增回归样本直接使用第 978 帧两块板角点，验证错误镜像解被排除、不同类别也能提供几何证据、单板证据不足时隐藏预测。500 帧直接 ONNX 推理的 CSV 与同帧检测缓存回放逐项一致。完整视频的独立世界/相机变换、半径、畸变投影复算通过。ROS 与 RViz 的在线检查结果见下方输出。

PDF 的云台 Pitch=1.34 rad 与此视频明显不吻合。保留该外参时，修复后 3150 帧里所有候选都没有足够一致的几何证据，算法不发布预测板。这是输入外参待标定的明确提示；不能用当前 0 rad 对照结果替代实测外参。平面 PnP、关键点和固定半径仍可能造成剩余误差。几何匹配阈值按这段 1440×1080 视频和 0.25 m 模型设置，换相机或机器人后应重新检查。

## 运行与成果

```bash
bash ros2_ws/build_ekf.sh
source /home/seb/armor_ekf_runtime/install/setup.bash
ros2 launch armor_ekf reprojection.launch.py \
  model_path:="$PWD/01_神经网络/yolo_pose/final_model/best.onnx" \
  video_path:="$PWD/00_题目原件/videos/test.mp4" \
  reprojection_config:="$PWD/ros2_ws/src/armor_ekf/config/reprojection_video_diagnostic.yaml"
rviz2 -d ros2_ws/rviz/armor_reprojection.rviz
```

`rviz2` 在另一个终端运行并加载相同 ROS 环境。图像话题为 `/armor/reproject/image_raw`。
