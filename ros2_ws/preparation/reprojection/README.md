# 重投影考核：准备记录

准备日期：2026-10-09。现已实现，验证结果及运行方式见 [重投影报告](../../src/armor_ekf/REPROJECTION_VERIFICATION.md)。本文保留准备推导。

## 考核目标

按[题目原件“重投影”一节](../../../00_题目原件/暑假考核.pdf)：用一块已识别装甲板在世界系下的位置与姿态，推算同一机器人的其余三块装甲板，并把可见装甲板投影回图像显示。公式中的 robot center、radius、z 关系和 90° 装甲板间隔以 PDF 为准。

## 已有工程条件

- `YawEstimate.pose` 已提供选择装甲板在 `odom` 下的完整位置和四元数；`observed_yaw` 是同一姿态向外法向在 odom XY 平面的角度。
- 坐标变换实现及TF链已完成；共享 `TransformChain` 可取 `T_odom_camera_optical_frame`，用逆矩阵转回 `camera_optical_frame`。
- YOLO检测、PnP、框关联和选中板已经工作。缓存检测和已完成的世界系视频回放可直接复用，不用训练或重新导出模型。
- 相机尺寸、内参、畸变、图像为 1440×1080 BGR8，装甲板为 0.135×0.055 m 均已有配置。
- OpenCV `projectPoints` 已用于PnP重投影误差计算；现有 `Pipeline::annotate`、ROS标注图像话题、offline和replay都可挂接同一套投影代码。
- 考核默认机器人半径为 0.25 m；装甲板 z 等于机器人中心 z；其余装甲板默认 Pitch=15°、Roll=0°。

## 几何关系与角度方向

PDF 位置公式为：

```text
x_i = x_c - r cos(yaw_pdf_i)
y_i = y_c - r sin(yaw_pdf_i)
z_i = z_c
yaw_pdf_i = yaw_pdf_0 + π/2 · i
```

从已知板恢复机器人中心：

```text
x_c = x_0 + r cos(yaw_pdf_0)
y_c = y_0 + r sin(yaw_pdf_0)
z_c = z_0
```

这里有一个必须在实现时明确的约定：当前PNP的 `observed_yaw` 来自装甲板向外法向 `n`，而 PDF 的减号公式把 `yaw_pdf` 写成从板位置指回机器人中心的方向。几何自洽的映射是：

```text
yaw_pdf_0 = wrap(yaw_pnp_0 + π)
yaw_pnp_i = wrap(yaw_pdf_i + π)
```

这样从中心指向板的位置方向与PNP向外法向一致，同时完全保留 PDF 的减号公式。不能把PNP外法向角直接代进 `yaw_pdf`；那会把板放在外法向的反方向。这个 π 映射是依据已有PNP帧轴定义和PDF位置公式的推导，实际实现会用同帧其它可见检测板检验它。

姿态采用 REP-103 世界轴。完整坐标架转换为 `R_out_i = Rz(yaw_pdf_i) Ry(pitch_pdf) Rx(roll_pdf) Rz(π)`，不能只替换 Yaw。Roll=0 时，转换后的外法向系 Pitch 为 −15°；PDF 内法向系仍为 +15°。索引 0 使用当前检测板的测量姿态和中心，不以默认15°覆盖实测姿态；其它板使用默认几何姿态。

## 样本数值

用已完成世界系回放的第0帧作推导示例：PNP装甲板位置约 `(0.479865, -0.069263, -4.409060) m`，外法向Yaw约 `2.845573 rad`。转换后 `yaw_pdf_0≈-0.296020 rad`，机器人中心约 `(0.718991, -0.142192, -4.409060) m`。此数值仅帮助检查公式实现；视频没有中心位置或Yaw真值。

## 实现方案

1. 新增 `reprojector.hpp/.cpp` 纯几何模块；输入选中板的 odom Pose、相机参数和尺寸，输出 4 个板各自的世界Pose、相机Pose、像素四角、正深度/图像相交/朝向标志；图像内不代表未被遮挡。
2. 每帧有有效选中板且 `header.frame_id=odom` 时才计算。按公式从板0求中心，再生成板1–3。漏检帧不根据消息里的零值Pose造目标，也不把旧预测标到新图像上。
3. 每块板的局部角点沿用PnP模型 `(0, ±width/2, ±height/2)`。先将角点从装甲板变换到odom，再经 `T_odom_camera_optical_frame⁻¹` 转到 optical，相机畸变使用现有 `camera_matrix` 与 `distortion`，最后用OpenCV `projectPoints` 生成像素坐标。
4. 距相机为负、角点深度接近零、坐标非有限的板不画；部分出界的多边形按图像边缘裁剪。图上区分实测板与预测板，并标注相对板索引、图像内数量和方向。
5. 用布尔参数和 `reprojection.launch.py` 启用该功能，保持 `world.launch.py` 的坐标变换结果不变。ROS发布独立 `/armor/reproject/image_raw` 标注图像；离线和检测缓存回放可生成完整 annotated.mp4。

## 验证计划

- 使用给定中心和一组已知Yaw生成四个装甲板，逐个反推中心；检查位置间距0.25 m、板间角度90°、所有结果共享同一中心。
- 用合成世界Pose生成角点，经过 Odom→camera 投影后用PNP恢复，再还原世界Pose和中心；测试角度环绕、俯仰符号和相机畸变。
- 输入板的投影角点与原PNP角点应落在原有像素重投影误差范围内。
- 对同一帧其它可见装甲板，计算投影轮廓 IoU/中心误差；同时检查外法向和 Pitch 符号的候选解释，确认 π 映射、顺/逆时针索引与真实图像一致。
- 检查相机视野内/外、边缘裁剪、遮挡导致无框、目标切换、目标丢失和消息 `detection_valid=false` 时不产生伪投影。
- 完整视频生成叠加结果；ROS订阅检查源时间戳、frame、有效板数量，RViz核对odom位姿和图像标注。

## 当前限制

PDF明确给了几何默认值，但没有实测机器人中心真值、真实板中心到机器人中心的精确半径或永久物理板标签。0.25 m、15°、0°都应暴露为ROS参数，保留默认值。真实检测板投影不吻合时，先检查坐标轴、角度方向及Pitch符号，并对照同帧板间布局；不能靠移动覆盖图形掩盖系统误差。

ROI/PnP误差之外，世界Yaw对实拍准确度仍没有真值背书。该考核可验证公式、自洽转换和图像投影吻合度，不应据此宣称绝对位置精度。
